# prototype — 회의 실시간 전사 웹 프로토타입

회의 실시간 전사 웹 화면 (로컬 실행). 마이크 소리를 받아 브라우저에 전사문을 실시간으로 보여줌.

- 말하는 중의 글자가 타이핑되듯 나타나고, 발화가 끝나면 확정됨
- 스트리밍 STT가 놓친 말(화자가 틈 없이 바뀔 때의 대답 등)을 VAD로 찾아 다시 인식하고, 시각에 맞는 자리에 "보완" 표시와 함께 끼워 넣음
- 상단 "보완 N건" 버튼으로 보완된 줄만 모아 보고, 누르면 본문 위치로 이동
- 확정 줄마다 화자 번호 표시 ("화자 1" 등, 이름은 모름). 칩 옆 숫자는 판단 때의 유사도 (기준 0.60 이상이면 같은 화자, 밑줄=새 화자가 됨, 기울임=짧아서 가장 가까운 화자에 붙임). 칩에 마우스를 올리면 근거와 모든 화자와의 유사도가 나옴. 상단 "보기 설정" → "유사도"로 숫자 끄기
- 화자가 너무 많이 나뉠 때: 상단 "보기 설정" → "참석자 N명"을 넣으면 그 인원이 다 찬 뒤로는 새 화자를 만들지 않고 가장 가까운 화자에 붙임 (`--max-speakers N`으로 시작 시 지정 가능). 이미 생긴 화자는 줄이지 않음. 화자 칩을 누르면 다른 화자에 합칠 수 있음 (지난 줄 번호도 바뀌고 이후 판단에도 반영, 되돌릴 수 없음)
- 모델 확신도가 0.3 미만인 글자에 점선 표시 (상단 "보기 설정"에서 끄기). 회의 2 정답 기준 표시된 글자 중 약 27%가 실제 오류, 오류의 약 24%가 표시됨 (nineouting-ref/stt_eval/meeting2/confidence_check.py)
- 보완 줄 전부와 확신도 낮은 글자가 있는 줄은 chunk-16·chunk-64 greedy로 다시 인식해, 결과가 다르면 "다른 결과" 버튼으로 보여줌 (진짜 2등 후보가 아님. sherpa-onnx 1.13.8에서 후보 목록을 꺼내는 방법은 찾지 못함)
- "다른 결과" 항목을 누르면 본문이 그 텍스트로 바뀜. 줄 끝 ✎로 직접 고칠 수 있음 (Enter 저장, Esc 취소). 고친 줄에는 "후보로 바꿈"/"직접 고침" 표시, 원래 결과는 선택지로 남아 되돌릴 수 있음. 고친 내용은 서버 기록과 자동 저장 파일에 반영됨
- 말이 아닌데 들어간 줄은 줄 끝 ✕로 지움 (저장 파일에는 `deleted`로 남고, 요약 쪽에는 삭제로 알림)
- STT가 아예 못 잡은 말은 줄 끝 ＋로 그 줄 다음에 직접 추가 (화자 선택 가능, "직접 추가" 표시). 시각은 앞 줄 끝과 다음 줄 시작의 가운데로 잡은 근사치
- 상단 "지우기"로 지금까지의 전사문을 지움 (서버 기록까지, 같은 주소를 연 다른 화면도 비워짐). 인식은 계속되고, 지운 시각보다 앞에서 시작한 줄(말하던 중이던 줄, 판단 대기 중이던 보완)은 나중에 도착해도 버림
- 맞장구·간투사로만 된 줄(네네, 그쵸, 어, 그 등)은 흐리게 하고 "맞장구"/"간투사" 표시. 상단 "보기 설정" → "맞장구 숨기기"로 숨김 (지우지 않음, 저장본에는 `kind`로 남음)
- 세션 (상단 버튼)
  - 서버를 켜면 세션이 시작되고 바로 전사함. 전사문은 줄이 바뀔 때마다 `transcripts/날짜_시각.jsonl`에 자동 저장 (비정상 종료에도 남음)
  - "● 녹음 시작": 같은 이름의 `.wav`로 녹음. 직전 최대 2분(세션 시작 이후분)도 함께 저장
  - "일시정지"/"계속": 전사와 녹음을 같이 멈춤. 멈출 때 무음 2.5초를 넣어 말하던 줄과 보완 판단을 마무리함
  - "완료": 세션 파일을 닫고 대기. 완료 뒤에 고친 내용도 그 세션 파일에 반영됨. "● 새 녹음 시작"을 누르면 화면을 비우고 새 파일로 시작
  - 파일 첫 줄 `_meta`의 `wav_t0`: 줄 시각(`start`) - `wav_t0` = wav 안의 시각
  - 녹음 전 참석자에게 알릴 것. `transcripts/`, `*.wav`, `*.jsonl`은 `.gitignore`로 깃에서 제외됨
- 요약 쪽 전송 (`app/summary_sender.py`, 2026-10-14 회의에서 정한 형식)
  - 세션 = 회의. 세션마다 `meeting_id`를 붙이고, 확정 줄을 10초마다 묶어 보냄 (`lines`, `edits`). 회의 시작·멈춤·재개·끝 알림은 바로 보냄
  - 시간은 회의 시작 기준 밀리초 정수. 줄 순서는 `start_ms` 기준이고 `id`는 순서가 아님 (보완 줄은 앞자리로 늦게 옴)
  - 고친 줄은 `edits`에 고친 횟수(`rev`)와 함께, 지운 줄은 `deleted: true`. `low_confidence`는 줄 글자 중 확률 0.3 미만이 20% 이상
  - `--summary-url`이 없으면 세션 파일 옆 `<이름>.outbox.jsonl`에만 기록. 주소를 주면 JSON으로 POST도 함 (실패하면 다시 보내지 않음)
  - 상단 "요약 전송" 버튼 → 오른쪽 상태창: 받는 곳, 보낸 묶음 수, 성공·실패, 다음 전송까지 남은 초, 다음 묶음에 들어갈 줄·수정·삭제, 보낸 기록(묶음별 결과와 보낸 JSON)
  - 본문 줄마다 시각 아래에 전송 상태 표시: `대기`, `#3`(3번 묶음으로 보냄), `수정 대기`, `#3 · 수정 #5`, 보내지 못했으면 `실패`
- `localhost`에서만 열림. 회의 내용을 외부로 보내지 않음. 녹음은 버튼을 눌렀을 때만 이 컴퓨터에 저장 (그 전에는 다시 인식용으로 최근 120초만 메모리에 둠)

## 실행

```bash
cd ~/Dev/nineouting-stt/prototype
.venv/bin/python app/server.py --list-devices      # 마이크 장치 번호 확인
.venv/bin/python app/server.py                     # 기본 마이크로 전사 → http://localhost:8765
```

| 옵션 | 내용 |
|---|---|
| `--device N` | 마이크 장치 번호 (`--list-devices`). 없으면 시스템 기본 입력 |
| `--input ffmpeg` | 마이크를 ffmpeg(avfoundation)로 받음. 기본은 sounddevice(CoreAudio). ffmpeg 입력은 말할 때 틱 잡음이 생김 (아래 참고) |
| `--diag` | 30초마다 입력 상태를 터미널에 출력: 실제 시간 대비 받은 소리(빠진 비율), 읽기 대기, 엔진·알림·저장·녹음 쓰기 시간, 대기열 최대, 입력 넘침 |
| `--wav 파일` | 마이크 대신 wav(16kHz 모노 16bit)를 실제 속도로 입력 (시험용) |
| `--summary-url 주소` | 요약 쪽 받는 주소 (JSON POST). 없으면 outbox 파일에만 기록 |
| `--send-period 초` | 요약 쪽 전송 주기. 기본 10 |
| `--meeting-id 값` | 첫 회의의 `meeting_id` (앱이 줄 값). 없으면 `m_날짜_시각` |
| `--save-dir 폴더` | 세션 전사·녹음 파일 폴더. 기본 `prototype/transcripts` |
| `--out 파일.jsonl` | 첫 세션의 전사 파일 경로 지정 (기본은 자동 이름). 줄이 바뀔 때마다 저장 |
| `--hotwords 파일 --hotwords-score 1.0` | 핫워드 (회의 용어). 흔한 말로 시작하는 단어는 넣지 않음 |
| `--blank-penalty 0.5` | 글자 안 냄(blank)에 주는 벌점. 기본 0.5. 빠지는 말이 줄고 틀린·낀 글자가 조금 늚. 0이면 끔 (아래 설정 근거) |
| `--chunk 16` | 글자가 더 자주 나옴(약 0.3초 단위) 대신 정확도 낮음. 기본 64 |
| `--no-recover` | VAD 보완 끄기 |
| `--no-diar` | 화자 번호 끄기 |
| `--max-speakers N` | 참석자 수 (0이면 자동). 화면에서도 바꿀 수 있음 |
| `--no-alt` | 다른 인식 결과 끄기 (인식기 2개를 덜 올림, 메모리 약 300MB 절약 추정) |
| `--models 경로` | 모델 폴더. 기본 `~/Dev/nineouting-ref/stt_models` |
| `--port N` | 기본 8765 |

- 종료: Ctrl+C
- 처음 마이크로 실행하면 macOS가 터미널 앱의 마이크 접근 허용을 물을 수 있음 (시스템 설정 → 개인정보 보호 및 보안 → 마이크)
- 마이크 입력은 sounddevice(PortAudio → CoreAudio). CoreAudio가 자기 스레드에서 0.1초 조각을 대기열에 넣어, 처리가 잠깐 늦어도 입력이 버려지지 않음. `--input ffmpeg`일 때만 PATH의 ffmpeg를 씀

## 설치

```bash
python3 -m venv .venv
.venv/bin/pip install --only-binary=:all: -r requirements.txt
```

모델은 복사하지 않고 nineouting-ref의 것을 씀.

STT 모델 출처: [kangkyu/icefall-asr-ko-streaming-zipformer-174m](https://huggingface.co/kangkyu/icefall-asr-ko-streaming-zipformer-174m) (Hugging Face, Apache 2.0)
- 우리 파일 7개(encoder·decoder·joiner chunk-16/64, tokens.txt)의 SHA256이 배포처 SHA256SUMS와 일치함 (2026-10-13 확인)
- 학습 데이터 약 6,500시간 (KsponSpeech 964시간 + AI Hub 약 5,500시간). AI Hub 데이터 이용 조건은 별도 확인 필요
- 학습용 원본 체크포인트 `epoch-99.pt`(623MB)와 chunk-32 ONNX도 배포됨 (우리는 받지 않음). 학습 레시피는 icefall `egs/librispeech/ASR/zipformer`
- 모델 카드 CER (KsponSpeech 평가, 작성자 측정): chunk-64 7.53%, chunk-32 7.82%, chunk-16 8.26%
- STT: `stt_models/zipformer-174m/*-chunk-64-left-128.int8.onnx`, `tokens.txt`
- VAD: `stt_models/speaker/silero_vad.onnx`
- 화자: `stt_models/speaker/nemo_en_titanet_small.onnx`

## 구조

| 파일 | 내용 |
|---|---|
| `app/engine.py` | 메인 스트리밍 STT + VAD 보완. 소리를 넣으면 partial / final / recovered 이벤트를 냄 |

## 설정 근거

nineouting-ref/stt_eval/meeting2/ 의 실험 문서
- `stt_improve.md` (SCRUM-23): chunk-64, 후보 4, 핫워드 21개·가산점 1.0 추천
- blank penalty (2026-10-14, `review/decode_opts/`, 최대 10초 + 1초·중복 거르기 기준, 측정값)

  | blank penalty | 회의 1 CER · 대체·삭제·삽입 | 회의 2 CER · 대체·삭제·삽입 |
  |---|---|---|
  | 0 | 20.7% · 94·89·14 | 5.6% · 65·43·29 |
  | 0.25 | 19.6% · 107·60·19 | 5.5% · 66·34·34 |
  | **0.5 (기본)** | 19.8% · 111·47·30 | 5.7% · 74·23·41 |
  | 0.75 | 19.9% · 114·56·19 | 5.8% · 77·22·42 |
  | 1.0 | 20.9% · 93·57·49 | 6.5% · 79·24·56 |

  빠진 말은 화면에 안 보여 사용자가 고치기 어렵고 요약 쪽도 복원할 수 없음 → 전체 CER이 비슷한 0.25~0.5 중 삭제가 가장 적은 0.5.
  같이 잰 `reset_encoder`(회의 1 21.5%, 회의 2 5.4%), VAD로 말소리 밖을 0으로 바꿔 넣기(20.8%, 6.2%)는 채택하지 않음
- `scrum25_vad_recover.md` (SCRUM-25): VAD 보완. 회의 1 평가 구간 CER 26.5% → 20.8%, 삭제 162 → 76자 / 회의 2 4.9% → 5.1%, 삭제 53 → 32자 (실시간 동작, 기다림 2.0초). 보완 텍스트는 말소리 끝 약 2초 뒤에 붙음

- 화자 번호: TitaNet-small 임베딩을 발화마다 누적 비교 (`stt_eval/poc/summary.md` 4절). 설정 E = 유사도 0.60, 2초 미만 발화는 새 화자로 등록하지 않음. PoC 두 구간 DER 평균 8.2% (chunk-16 확정 발화 기준이라 chunk-64에서는 미검증)

## 확인한 것과 안 한 것

- wav(회의 1 평가 구간)를 실제 속도로 넣어 화면 동작 확인함 (2026-10-13): 타이핑, 확정, 보완 줄 제자리 끼우기, 콘솔 오류 없음
- 요약 쪽 전송을 wav 입력과 시험용 받는 서버로 확인함 (2026-10-14, 주기 5초로 줄여 시험): 보낸 11개와 받은 11개가 같음, 보완 줄이 앞 시각으로 늦게 옴, 같은 주기 안에서 두 번 고치면 `rev` 2만 감, 보내기 전에 지운 줄은 묶음에서 빠짐, 멈춤·재개·끝 알림. 실제 요약 쪽 FastAPI와는 아직 연결 안 함
- 세션 버튼을 wav 입력으로 확인함 (2026-10-13): 녹음 시작(직전 18초 포함), 일시정지·계속, 완료, 새 세션, 완료 뒤 고치기가 각 파일에 저장됨. 줄 시각 - `wav_t0` 위치에 실제 말소리가 있음 (구간 RMS로 확인). 마이크 입력으로는 확인하지 않음
- 마이크 입력 문제 (2026-10-14, 맥 내장 마이크)
  - ffmpeg avfoundation으로 받으면 말할 때마다 틱 잡음 (16kHz 변환·원래 형식 모두). 같은 마이크를 음성 메모·sounddevice로 받으면 깨끗함 (진 청취) → 기본 입력을 sounddevice로 바꿈
  - ffmpeg 입력 서버 세션들에서 실제 시간 대비 엔진에 들어간 소리가 약 11% 짧았음 (outbox 알림 시각 vs at_ms). ffmpeg 단독(파일·파이프)은 60초 녹음에 60.3초로 정상이고, 녹음 재생으로 잰 엔진 처리는 실시간의 0.07배 → 서버 안 원인은 미확정. sounddevice 입력에서 사라지는지 `--diag`로 확인 예정
  - 측정 스크립트: nineouting-ref `stt_eval/meeting2/review/live_1014/` (audio_check.py, feed_timing.py, session_drift.py)
- 화자 번호·보완 목록 패널·"최신으로" 버튼·휴대폰 폭(375px) 화면을 wav로 확인함 (2026-10-13). 화자 번호의 정확도는 재지 않음
- 짧은 대답(2초 미만)은 새 사람이어도 기존 화자 중 가장 가까운 사람으로 붙음 (설정 E의 부작용)
- 한 줄 안에서 화자가 바뀌면 한 사람으로 처리됨
- 보완 줄과 이웃 줄의 경계에서 한 단어가 겹칠 수 있음 (보완 구간 앞뒤 0.2초 여유 때문)
