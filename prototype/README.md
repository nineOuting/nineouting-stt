# prototype — 회의 실시간 전사 웹 프로토타입

회의 실시간 전사 웹 화면 (로컬 실행). 마이크 소리를 받아 브라우저에 전사문을 실시간으로 보여줌.

- 말하는 중의 글자가 타이핑되듯 나타나고, 발화가 끝나면 확정됨
- 스트리밍 STT가 놓친 말(화자가 틈 없이 바뀔 때의 대답 등)을 VAD로 찾아 다시 인식하고, 시각에 맞는 자리에 "보완" 표시와 함께 끼워 넣음
- 상단 "보완 N건" 버튼으로 보완된 줄만 모아 보고, 누르면 본문 위치로 이동
- 확정 줄마다 화자 번호 표시 ("화자 1" 등, 이름은 모름). 칩 옆 숫자는 판단 때의 유사도 (기준 0.60 이상이면 같은 화자, 밑줄=새 화자가 됨, 기울임=짧아서 가장 가까운 화자에 붙임). 칩에 마우스를 올리면 근거와 모든 화자와의 유사도가 나옴. 상단 "보기 설정" → "유사도"로 숫자 끄기
- 화자가 너무 많이 나뉠 때: 상단 "보기 설정" → "참석자 N명"을 넣으면 그 인원이 다 찬 뒤로는 새 화자를 만들지 않고 가장 가까운 화자에 붙임 (`--max-speakers N`으로 시작 시 지정 가능). 이미 생긴 화자는 줄이지 않음. 화자 칩을 누르면 다른 화자에 합칠 수 있음 (지난 줄 번호도 바뀌고 이후 판단에도 반영, 되돌릴 수 없음)
- 모델 확신도가 0.3 미만인 글자에 점선 표시 (상단 "보기 설정"에서 끄기). 회의 2 정답 기준 표시된 글자 중 약 27%가 실제 오류, 오류의 약 24%가 표시됨 (nineouting-ref/stt_eval/meeting2/confidence_check.py)
- 보완 줄 전부와 확신도 낮은 글자가 있는 줄은 chunk-16·chunk-64 greedy로 다시 인식해, 결과가 다르면 "다른 결과" 버튼으로 보여줌 (진짜 2등 후보가 아님. sherpa-onnx 1.13.8에서 후보 목록을 꺼내는 방법은 찾지 못함)
- "다른 결과" 항목을 누르면 본문이 그 텍스트로 바뀜. 줄 끝 ✎로 직접 고칠 수 있음 (Enter 저장, Esc 취소). 고친 줄에는 "후보로 바꿈"/"직접 고침" 표시, 원래 결과는 선택지로 남아 되돌릴 수 있음. 고친 내용은 서버 기록과 자동 저장 파일에 반영됨
- 말이 아닌데 들어간 줄은 줄 끝 ✕로 지움 (저장 파일에는 `deleted`로 남고, 요약 쪽에는 삭제로 알림)
- STT가 아예 못 잡은 말은 줄 끝 ＋로 그 줄 다음에 직접 추가 (화자 선택 가능, "직접 추가" 표시). 시각은 앞 줄 끝과 다음 줄 시작의 가운데로 잡은 근사치
- 상단 "지우기"로 지금까지의 전사문을 지움 (서버 기록까지, 같은 주소를 연 다른 화면도 비워짐). 인식은 계속되고, 지운 시각보다 앞에서 시작한 줄(말하던 중이던 줄, 판단 대기 중이던 보완)은 나중에 도착해도 버림
- 맞장구·간투사로만 된 줄(네네, 그쵸, 어, 그 등)은 흐리게 하고 "맞장구"/"간투사" 표시. 상단 "보기 설정" → "맞장구 숨기기"로 숨김 (지우지 않음, 저장본에는 `kind`로 남음)
- 세션 (상단 버튼)
  - 서버를 켜면 세션이 시작되고 바로 전사함. 전사문은 줄이 바뀔 때마다 `transcripts/날짜_시각.jsonl`에 자동 저장 (비정상 종료에도 남음)
  - "● 녹음 시작": 같은 이름의 `.wav`로 녹음. 직전 최대 2분(세션 시작 이후분)도 함께 저장
  - "일시정지"/"계속": 전사와 녹음을 같이 멈춤. 멈출 때 무음 2.5초를 넣어 말하던 줄과 보완 판단을 마무리함
  - "완료": 세션 파일을 닫고 대기. 완료 뒤에 고친 내용도 그 세션 파일에 반영됨. "● 새 녹음 시작"을 누르면 화면을 비우고 새 파일로 시작
  - 파일 첫 줄 `_meta`의 `wav_t0`: 줄 시각(`start`) - `wav_t0` = wav 안의 시각
  - 녹음 전 참석자에게 알릴 것. `transcripts/`, `*.wav`, `*.jsonl`은 `.gitignore`로 깃에서 제외됨
- 요약 쪽 전송 (`app/summary_sender.py`, 2026-10-14 회의에서 정한 형식)
  - 세션 = 회의. 세션마다 `meeting_id`를 붙이고, 확정 줄을 10초마다 묶어 보냄 (`lines`, `edits`). 회의 시작·멈춤·재개·끝 알림은 바로 보냄
  - 시간은 회의 시작 기준 밀리초 정수. 줄 순서는 `start_ms` 기준이고 `id`는 순서가 아님 (보완 줄은 앞자리로 늦게 옴)
  - 고친 줄은 `edits`에 고친 횟수(`rev`)와 함께, 지운 줄은 `deleted: true`. `low_confidence`는 줄 글자 중 확률 0.3 미만이 20% 이상
  - `--summary-url`이 없으면 세션 파일 옆 `<이름>.outbox.jsonl`에만 기록. 주소를 주면 JSON으로 POST도 함 (실패하면 다시 보내지 않음)
  - 상단 "요약 전송" 버튼 → 오른쪽 상태창: 받는 곳, 보낸 묶음 수, 성공·실패, 다음 전송까지 남은 초, 다음 묶음에 들어갈 줄·수정·삭제, 보낸 기록(묶음별 결과와 보낸 JSON)
  - 본문 줄마다 시각 아래에 전송 상태 표시: `대기`, `#3`(3번 묶음으로 보냄), `수정 대기`, `#3 · 수정 #5`, 보내지 못했으면 `실패`
- 백엔드 전송 (`app/backend_sender.py`, CN팀 2장 2.2 + AI팀 추가 필드, 2026-10-15 확정)
  - `{"segments": [...]}`. 말하는 중 줄은 `{seq, rev, text, startMs, final: false}`, 확정·보완 줄은 여기에 `endMs, lowConfidence, kind, recovered`를 더해 `final: true`
  - 같은 줄은 같은 `seq`(엔진 줄 번호)로 매번 줄 전체 글자를 보냄. `rev`는 줄마다 1부터 늘어나고, 확정한 줄은 다시 보내지 않음
  - 0.5초마다 바뀐 줄만 보냄. 보내지 못하면 다음 주기에 그 줄들의 최신 상태를 다시 보냄. 연결은 유지해 재사용
  - 보완 줄은 말하는 중 단계 없이 확정으로 바로 오고 앞 시각에 끼워질 수 있음 (`seq`는 시간 순서가 아님)
  - 화면에서 고치거나 지우거나 추가한 줄, 화자 번호는 보내지 않음 (정식 서비스에서는 백엔드가 처리, 발화자 구분은 하지 않기로 함)
- `localhost`에서만 열림. 회의 내용을 외부로 보내지 않음. 녹음은 버튼을 눌렀을 때만 이 컴퓨터에 저장 (그 전에는 다시 인식용으로 최근 120초만 메모리에 둠)

## 실행

```bash
cd ~/Dev/nineouting-stt/prototype
.venv/bin/python app/server.py --list-devices      # 마이크 장치 번호 확인
.venv/bin/python app/server.py                     # 기본 마이크로 전사 → http://localhost:8765
```

| 옵션 | 내용 |
|---|---|
| `--device N` | 마이크 장치 번호 (`--list-devices`). 없으면 시스템 기본 입력. ffmpeg 입력 때와 번호가 다름 (예전 `--device 0`은 이제 마이크가 아닐 수 있음). 마이크가 아닌 번호면 시작할 때 마이크 목록을 알려 주고 끝냄 |
| `--input ws` | 마이크 대신 브라우저(회의록 작성자)가 WebSocket으로 보내는 소리를 받음 (정식 서비스 구조). `--ws-host`(기본 127.0.0.1), `--ws-port`(기본 8770). 아래 "브라우저 입력" 참고 |
| `--input ffmpeg` | 마이크를 ffmpeg(avfoundation)로 받음. 기본은 sounddevice(CoreAudio). ffmpeg 입력은 말할 때 틱 잡음이 생김 (아래 참고) |
| `--diag` | 30초마다 입력 상태를 터미널에 출력: 실제 시간 대비 받은 소리(빠진 비율), 읽기 대기, 엔진·알림·저장·녹음 쓰기 시간, 대기열 최대, 입력 넘침. 없어도 마이크 소리가 빠지면(최근 30초에 1% 이상, 또는 입력 넘침) `[경고]` 한 줄은 나옴 |
| `--wav 파일` | 마이크 대신 wav(16kHz 모노 16bit)를 실제 속도로 입력 (시험용) |
| `--summary-url 주소` | 요약 쪽 받는 주소 (JSON POST). 없으면 outbox 파일에만 기록 |
| `--send-period 초` | 요약 쪽 전송 주기. 기본 10 |
| `--backend-url 주소` | 백엔드 주소 (예: `http://meeting-service:8080`). `POST {주소}/internal/meetings/{meeting_id}/transcripts`. 없으면 `<세션>.backend.jsonl`에만 기록 |
| `--backend-period 초` | 백엔드 전송 주기. 기본 0.5. 그사이 바뀐 줄만 보냄 |
| `--meeting-id 값` | 첫 회의의 `meeting_id` (앱이 줄 값). 없으면 `m_날짜_시각` |
| `--save-dir 폴더` | 세션 전사·녹음 파일 폴더. 기본 `prototype/transcripts` |
| `--out 파일.jsonl` | 첫 세션의 전사 파일 경로 지정 (기본은 자동 이름). 줄이 바뀔 때마다 저장 |
| `--hotwords 파일 --hotwords-score 1.0` | 핫워드 (회의 용어). 기본 `app/hotwords.txt`(31개), 끄려면 `--hotwords ''`. 흔한 말로 시작하는 단어나 짧은 말(디비 등)은 넣지 않음 (아래 설정 근거) |
| `--blank-penalty 0.5` | 글자 안 냄(blank)에 주는 벌점. 기본 0.5. 빠지는 말이 줄고 틀린·낀 글자가 조금 늚. 0이면 끔 (아래 설정 근거) |
| `--chunk 16` | 글자가 더 자주 나옴(약 0.3초 단위) 대신 정확도 낮음. 기본 64 |
| `--no-recover` | VAD 보완 끄기 |
| `--no-diar` | 화자 번호 끄기 |
| `--max-speakers N` | 참석자 수 (0이면 자동). 화면에서도 바꿀 수 있음 |
| `--no-alt` | 다른 인식 결과 끄기 (인식기 2개를 덜 올림, 메모리 약 300MB 절약 추정) |
| `--models 경로` | 모델 폴더. 기본 `~/Dev/nineouting-ref/stt_models` |
| `--port N` | 기본 8765 |

### 확인용 화면 세 가지

브라우저 입력(`--input ws`)과 가짜 백엔드를 함께 켰을 때 쓰는 화면. 모두 시험·확인용이고 실제 FE가 아님.

```text
/sender (작성자 브라우저 흉내) ──소리──▶ STT 서버 ──0.5초──▶ 가짜 백엔드
   ▲          8765 = STT 개발 화면                     8767 = 받은 것 확인
   └──────────────────────────── 자막 ─────────────────────┘
```

| 주소 | 화면 | 보는 것 | 실서비스에서 |
|---|---|---|---|
| `http://localhost:8765/sender` | **보내기 + 자막 + 지연** (`tools/mic_sender.html`) | 위: 마이크 → STT 보내기(시작·멈춤·재개·종료, 브라우저 음성 처리 켬/끔, 끊고 다시 붙기). 아래: 가짜 백엔드에서 받은 자막. 줄마다 입력 시각(그 말을 마이크로 받은 실제 시각), 첫 표시(+말 시작부터), 확정(+말 끝부터), 위쪽에 지연 중앙값·최댓값 | 회의록 작성자 화면 (보내기 + 백엔드가 내려주는 자막) |
| `http://localhost:8765` | **STT 개발 화면** (`app/static/index.html`) | STT가 인식한 결과를 바로 봄. 다른 결과 후보, 화자 번호, 확신도, 요약 전송 상태창. 시각은 엔진 시각이라 멈출 때마다 2.5초씩 앞섬(마무리용 무음 포함) | 없음 (STT 서버에는 화면이 없음) |
| `http://localhost:8767` | **가짜 백엔드 화면** (`tools/mock_backend.py`) | 백엔드가 받은 요청 기록(간격, 줄 수, 원문 JSON), 2.2 규칙으로 합친 자막, 규칙 위반 수, "10초 동안 실패(503)" 시험 버튼 | 백엔드 (meeting-service) 쪽 확인 |

- 실서비스 기준 시각(회의 시간)은 `/sender`의 "만든 소리"와 자막, 8767이 같음. 8765만 다름
- 지연 측정은 `/sender`에서 브라우저 마이크로 보낼 때만 나옴 (입력 시각을 브라우저가 기록하므로). 마이크 장치 자체의 지연은 포함되지 않고, 실서비스에서는 실제 백엔드·Gateway를 거치는 만큼 더 걸릴 수 있음
- 포트 바꾸기: STT 화면은 `--port`, WebSocket은 `--ws-port`, 가짜 백엔드는 `tools/mock_backend.py --port N` (그때는 STT의 `--backend-url`과 `/sender` 자막 칸의 주소도 같이 바꿈)

### 브라우저 입력 (`--input ws`)

정식 서비스처럼 브라우저가 마이크 소리를 WebSocket으로 보냄 (CN팀 2장 2.1 검토 확정).

```bash
.venv/bin/python tools/mock_backend.py                                         # 터미널 1 (가짜 백엔드, 선택)
.venv/bin/python app/server.py --input ws --backend-url http://127.0.0.1:8767  # 터미널 2
```

- 시험용 보내는 화면: `http://localhost:8765/sender` (`tools/mic_sender.html`, 실제 FE 아님). 시작·멈춤·재개·종료, 에코 제거·잡음 억제·자동 음량 켬/끔(기본 끔), "끊고 3초 뒤 다시 붙기"(장애 뒤 몰아 보내기 시험)
- 같은 화면 아래 자막 칸: 가짜 백엔드가 합친 자막을 구독해 보여줌 (보내기 → STT → 백엔드 → 자막, 실서비스의 작성자 화면과 같은 경로). 가짜 백엔드는 SSE로 내려주지만 실제 백엔드는 WebSocket 예정. 실서비스에는 STT 화면(8765)이 없고, 8765는 엔진 시각(멈춤 때 넣은 무음 포함)을 보여주므로 회의 시간과 다를 수 있음
- 규약
  - 바이너리: 16kHz 모노 16비트 PCM(little-endian), 100ms = 3,200바이트
  - 텍스트(JSON): `{"type":"start","meetingId":"…","offsetMs":0}`, `{"type":"pause"}`, `{"type":"resume"}`, `{"type":"end"}`
  - 서버 응답: `{"type":"ready","meetingId","meetingMs"}`(서버가 받은 그 회의 소리 길이), `{"type":"ended"}`, `{"type":"error","message"}`
- 서버를 켜면 대기하다가 `start`를 받으면 그 `meetingId`로 세션을 엶. 다른 `meetingId`가 오면 이전 회의를 닫고 새로 엶
- 같은 회의로 다시 연결: `start`의 `offsetMs`(이어서 보낼 소리가 회의 몇 ms부터인지)로 위치를 맞춤. 이미 받은 부분은 버리고 빈 시간은 무음으로 채움. 밀린 소리가 1초 넘게 쌓인 동안은 말하는 중 줄을 백엔드로 보내지 않음
- 회의(연결)는 한 번에 하나. 두 번째 연결은 1008로 거절. 작성자 확인은 백엔드 몫이라 하지 않음
- 멈출 때 말하던 줄을 마무리하려고 무음 2.5초를 엔진에 넣는데, 브라우저가 세는 회의 시간에는 없으므로 백엔드·요약 쪽으로 보내는 시각에서 뺌. 세션 파일 `_meta.gaps`에 기록
- 정식 서비스에서는 브라우저가 Gateway를 거쳐 연결함. 로그인 정보 전달, 경로, 연결 유지 시간 제한은 CN팀과 맞출 것 (ping은 websockets 기본값 20초)

### 백엔드 전송을 눈으로 확인하기 (가짜 백엔드)

```bash
.venv/bin/python tools/mock_backend.py                                      # 터미널 1 → http://localhost:8767
.venv/bin/python app/server.py --device 2 --backend-url http://127.0.0.1:8767  # 터미널 2
```

- `http://localhost:8765`(STT 화면)와 `http://localhost:8767`(가짜 백엔드 화면)을 나란히 띄우고 말함
- 가짜 백엔드 화면 왼쪽: 받은 줄을 2.2 규칙(같은 `seq` 덮어쓰기, `rev`가 클 때만, 확정은 덮지 않음, `startMs` 순)으로 합친 자막. 회색 기울임 = 말하는 중, 노란 강조·"보완" = 보완 줄, 점선 = `lowConfidence`
- 오른쪽: 받은 요청 수·확정·보완 줄 수, 규칙 위반 수(옛 `rev`, 확정 뒤 다시 옴), 요청 기록(간격, 줄 수, 결과, 원문 JSON)
- "10초 동안 실패(503)" 버튼: 그동안 503으로 답함. STT는 0.5초마다 다시 시도하고, 끝나면 밀린 줄을 다시 보냄
- STT 화면에서 고치거나 지운 줄은 가짜 백엔드에 반영되지 않음 (정식 서비스에서는 백엔드가 처리해 STT가 보내지 않음)
- 포트를 바꾸려면 `--port N`

- 종료: Ctrl+C
- 처음 마이크로 실행하면 macOS가 터미널 앱의 마이크 접근 허용을 물을 수 있음 (시스템 설정 → 개인정보 보호 및 보안 → 마이크)
- 마이크 입력은 sounddevice(PortAudio → CoreAudio). CoreAudio가 자기 스레드에서 0.1초 조각을 대기열에 넣어, 처리가 잠깐 늦어도 입력이 버려지지 않음. `--input ffmpeg`일 때만 PATH의 ffmpeg를 씀
